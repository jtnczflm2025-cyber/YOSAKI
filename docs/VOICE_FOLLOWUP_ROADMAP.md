| 2. AI 语气规划最小版本 | 一条完整回复只分析一次，生成可编辑标注并用于短日语 HTTP 朗读 | 模型标注器、校验器、预览/小标、缓存、短样本听评 | 合成正文逐字可追溯；无标注与失败回退正确；用户认可限定样本的听感 |
| 3. 短段串行朗读 | 先两短段衔接，再同策略超过2000字整篇 | 约200字/句界后备、实际请求预算、串行计量/缓存/取消；不要求整篇恰两请求 | 两短段及整篇分别记真实结果；无漏读重复换序、首错即停，历史unknown保留 |
| 4. 日常接入与表达扩展 | 把已验证的规划接入自动朗读和连续通话，扩展 WS 与语言范围 | 分入口开关、规划等待/取消、HTTP/WS 兼容表、中日混合样本 | 关闭仍走已交付路径；新增等待可取消；旧轮次不播放；HTTP/WS 分别有证据 |
| 5. 稳定性与设备交付 | 验证长用、设备切换、扬声器及故障恢复 | 分层设备矩阵、回声方案、长通话/启停/故障报告、运维说明 | 无重复提交与回声循环，资源有界；每种通过范围明确；文字可继续使用 |
| 6. 边生成边送读研究 | 判断能否取得可验证的片段级展示许可，再决定实施 | 连接器协议研究、门控与撤销设计、可行性结论；可行后才做隔离原型 | 不以 token delta 代替展示许可；不绕过现有门控；不可行时可按研究结论收口 |

推荐主线：1 → 2 → 3 → 4 → 5。第 6 步独立研究，不作为前五步交付前提。第 4 步的短文本接入不必等待第 3 步的所有长文本语言样本；只需明确禁用尚未验证的组合，不用无关待办阻塞已经通过的能力。每一步先交付当前范围，再决定下一步。

## 3. 第 1 步：规则与接口定稿

### 目标

形成能够直接指导编码、让用户能审阅的设计。先固定“表达意图”和“供应商标签”的区别，避免把每句都套上一个标签。

### 产品规则

- 角色声音基线为“克制”；平静、含蓄时可以整条零标注。不得为了丰富而强行添加笑、叹气或哭声。
- 支持按段标注、按句标注和自动选择粒度；同一条回复可只标少数句子。分句标注不等于每句都新建一次合成请求。
- “不加额外标注”表示沿用角色基线；“关闭 AI 语气规划/普通无标签朗读”仍是独立入口。现有手选 thoughtful 的含义不改写为克制。
- 定稿时明确克制的实际渲染方式：在现已验证且启用的范围可复用 restrained 基线；普通无标签模式仍保持无标签。不得假定任意音色、语言和 WS 的空标签都必然产生克制听感；未验证组合单列。
- 聊天正文正常展示；语气默认隐藏，可选择显示句旁小标。点击小标可以查看、修改或删除建议；整条可关闭规划。编辑语气只影响音频表达，不改原消息。
- 首版不做逐音节时间轴、强制对齐或音频波形编辑；小标不宣称精确定位当前播放到哪个词。

### 技术契约

1. 只处理完整生成、已保存且通过既有展示核验的可朗读正文。
2. 程序先生成稳定的段/句 ID 与正文指纹；已有 Markdown/不可朗读内容过滤继续由可信代码负责。
3. 模型一次分析整条回复，返回“片段 ID → 表达意图”列表；允许空列表。不让模型返回一份改写后的朗读正文。
4. 模型输入首版使用已核验正文、有限的公开对话语境及声音设定；不采集隐藏推理，不新增心理/记忆写入。若复用既有只读心理快照，沿用每 generation 最多一次及既有权限范围。
5. 可信程序校验片段归属、重复/冲突、数量上限、候选白名单、版本和指纹，再映射到指定 HTTP/WS 路径支持的标签。供应商方括号字符串不由模型任意拼接。
6. 规划失败、超时或无效返回时沿用已验证的回退路径；取消、换角色、换消息、撤权时直接停止，不能因回退重新触发旧轮次。真实请求结果未知不自动再调用模型或合成。
7. 编辑后的新表达方案有新指纹；旧音频不可冒充新方案，旧普通缓存仍可使用。

### 输出与收口

在独立路线文档中补齐字段、状态、时限、模型来源、标签兼容性、上下文范围、计量和 UI 草图/文案。核对 HTTP/WS 文档及本地 Adapter 的真实契约，不能把官网 Enhance 按钮直接当成可调用的公开 Enhance API。

首版候选可以围绕平静/无额外表达、若有所思、轻柔、无奈、冷幽默等意图讨论；具体供应商标签、作用范围、强度和是否开放，须由能力核对与试听确定，不在规划中冒称已支持。

### 3.1 本机第 1 步设计交付（2026-11-18）

第 1 步主体设计已获用户认可。本批按新增授权修订第 3.3 节，并完成 `expression-annotation-2` 的第 2 步隔离实现与模拟。第 3～5 步未开始，第 6 步独立待研究。新增 AI 能力未接日常服务或真实 Provider，完整证据见[第 2 步验收](VOICE_EXPRESSION_STEP2_EVIDENCE.md)。

**与当前实现的边界。** 当前 `automatic_expression.py` 的 `v3-auto-1` 是规则规划，不调用额外模型。`expression_product.py` 现有 `none/thoughtful/auto` 保持原义。新 AI 规划单独设为 `ai_expression`，默认关闭，不能静默把已开启的规则模式升级成收费分析。显式手选优先于 AI，整条关闭优先于所有建议。

**克制基线。** “不加额外标注”是计划内的留白，允许 `annotations=[]`，不强制笑声、低语或叹气。只有用户已开启、且当前日语单段 HTTP 规则条件成立时，才复用已验的 restrained 渲染；其他情况普通朗读。现有 restrained 实现可映射 `[thoughtful] `，这是特定规则的实际渲染，不把所有 thoughtful 改名为克制，也不承诺无标签会自动降低音高。预览分开显示请求模式、有效基线、额外标注和最终标签。“关闭 AI 规划／普通无标签朗读”必须明确不添加基线标签。

### 3.2 输入、来源与模型返回

| 对象 | 必须绑定的字段及规则 |
|---|---|
| 来源 | 服务端从已保存助手消息读取 `owner_id/character_id/conversation_id/message_id`、当前 generation（存在时）、正文版本和哈希、完成及展示资格。客户端不能替换正文或归属。没有显式正文版本时，使用正文＋状态＋既有版本信息的内容指纹，不编造数据库列。 |
| 安全文档 | 复用现有过滤器，聊天正文原样保留。生成 `source_sha256/safe_text_sha256/filter_version/fragmenter_version`，保留安全文本到原来源的映射。被过滤的 Audio Tags 不成为建议输入或可直通标签。 |
| 段句索引 | 程序生成 `fragment_id/kind/parent_id/start/end`，区间为安全文本 Unicode 码点的半开区间，保留换行。ID 绑定安全正文指纹、分句版本及区间。前端经明确的码点与 UTF-16 映射定位，不能直接混用下标。 |
| 计划身份 | `plan_id/revision/input_sha256`、来源绑定、Profile revision、Voice ID 摘要、告知版本、粒度、规划模型身份及有效参数、提示版本、规则/渲染版本。ID 本身不授予派发权限。 |
| 模型输出 | 严格 JSON，仅 `schema_version:1`、`input_sha256`、`annotations:[{fragment_id,intent}]`。允许空数组。不接收改写正文、自由标签、理由、私有推理或任意新增键。片段 ID 必须来自本次输入。 |
| 人工修订 | 单独记录修订版本和用户操作。只能在可信片段上选择已开放意图、移除建议或关闭整条规划，不能借编辑入口注入任意标签。修改只产生新计划，不改聊天消息。 |

粒度为 `paragraph/sentence/auto`。同一计划可稀疏标注段或句，但同一区间重复、段与子句重叠、相互冲突均整份拒绝，不让“最后一项覆盖”掩盖错误。首版最多 32 个候选片段、8 项标注；超限零规划派发或拒绝模型返回，不截断原文。标注粒度独立于 SpeechPlan 请求分段。

合成契约例：安全正文为 `今夜は静かだ。\n\n少し考えてから話そう。`，程序生成两个段及相应句 ID。模型可以返回以下结构（占位值由本次真实输入指纹和程序生成 ID 替换），也可以返回相同版本/指纹且 `annotations:[]`。模型不输出正文和供应商标签。

```json
{"schema_version":1,"input_sha256":"<本次输入的 SHA-256>","annotations":[{"fragment_id":"<第二段的可信 ID>","intent":"thoughtful"}]}
```

**有限上下文与一次分析。** 完整回复一次规划，不逐句调用。输入仅本条安全正文、同一对话最近至多两条已获准公开消息（合计最多 1000 码点）、声音人格（最多 1000 码点）与固定指令。最终完整模型消息最多 6000 码点，这是容量门控而非 token 换算。超限提示本条不适用，不静默截断人格或换模型。首版不附工具、记忆检索、摘要或隐藏推理，不修改日常聊天上下文构造。若显式允许既有 Psychology 输入，只取本 generation 已读取的同一只读快照中的白名单状态，首次最多读取一次；缺失就省略，不触发心理计算、写入或补查。快照身份计入输入指纹，重播不重新读取。

规划模型由用户明确选择的既有可用档案解析，预览固定档案版本、供应商、模型和实际有效参数，不自动猜选另一个账户或模型。拟定单次 **1 次规划、最多 512 输出 token、20 秒总期限、零重试**；派发前检查选定接口及最终请求体确实落实输出上限。不支持即零模型派发。输入字符门控不能代替接口 token 限制。完整真实请求、模型和输入数据范围在以后收费执行单冻结，本轮不读凭据、不查询目录。

### 3.3 意图与路径兼容矩阵

| 意图 | 当前可依据的映射 | 第 2 步边界 |
|---|---|---|
| 无额外表达 `inherit` | 不追加标签；可能沿用显式启用且适用的现有基线 | 空计划合法，未满足基线条件时普通朗读；预览如实展示实际标签。 |
| 若有所思 `thoughtful` | 现有 HTTP `[thoughtful] `，已有日语短句限定试听 | 可作为首版受控候选；新 AI 判断是否贴切仍待独立验证。 |
| 克制 `restrained` | 现有规则在限定条件下使用 thoughtful 渲染 | 复用原证据和开关，不把“克制”当成一个新供应商标签。 |
| 慵懒 `lazy` | 既有评测曾使用 `[relaxed]`，该短句未改善，不默认应用 | 候选，不进入首版自动发布白名单。 |
| 冷幽默 `dry_humor`、无奈 `resigned`、低语 `whisper`、轻笑 `chuckle` | 本地规则存在 sarcastic/sighs/whispers/chuckles 映射 | 仅有规则/模拟依据，不能当作日常听感通过；保留候选。 |
| 轻柔 `gentle` | 尚无本音色和当前路径的限定验证映射 | 保留语义候选，不凭英文名称拼标签。 |

只允许可信映射生成标签。按用户本批修订，明确区分日常开放与隔离候选。日常仍仅沿用现有受控克制规则、普通无标签和手选 thoughtful，不新增其他日常标签。隔离候选允许按段、按句、稀疏以及相邻句，在同一份单请求 HTTP 文本的多个合法位置插入白名单标签；允许 thoughtful、restrained、lazy、dry_humor、resigned、whisper、chuckle 及不加额外标签 inherit。gentle 没有已核实映射，仍拒绝。标签位置、空格、换行全部计入实际请求字符，不因标注粒度增加请求。多位置文本必须能完整预览并交给假 TTS，不再限制为整条一个前置标签。实际作用范围、相邻未标注句是否受影响、如何恢复克制均标为待听评；不发明重置标签，不将构造成功说成听感通过。

HTTP 复用本地 `POST /v1/text-to-dialogue`，`eleven_v4`、`mp3_44100_128`、`inputs:[{text,voice_id}]`，确定日语时 `language_code=ja`，settings 沿既有路径省略。实际完整文本含标签不超过当前单请求 2000 码点，超过则本步不适用，不临时换分段规则。当前基础 Planner 还有限制总计 8000 码点／8 段，保留不变。当前日常 WS 使用 `eleven_v4_turbo/pcm_24000` 的独立链路；普通 WS 已验不等于 AI 标签已验。第 2 步不接 AI 表达到 WS、连续通话、中文或混合语言，不改变这些入口现有普通播放能力。网站 Enhance 控件不被视作已接通的公开 API。

### 3.4 接口草案、状态与派发边界

以下 `/api/voice` 为未来产品契约。本批对应实现仅安装在独立实例的 `/api/voice-expression-lab`，来源为合成完整回复，使用独立本地 session，未注册日常路由。默认规划模型仍是无外呼能力的假模型。本批新增既有档案适配器及 `model_profile_id` 绑定，已通过实际 lab 路由注入假传输验证；lab 继续拒绝真实传输。真实模型派发与判断质量仍待另行批准。

| 操作 | 请求／返回与副作用 |
|---|---|
| `GET /messages/{id}/expression-source` | 只读返回资格、可信安全片段、能力与来源指纹。没有模型请求、心理更新或音频生成。 |
| `POST /messages/{id}/expression-plans` | 请求 `operation_id/input_sha256/profile_revision/model_profile_id/granularity` 及显式规划同意，服务端重建输入后比较。原子占用一次规划身份及其独立预算，再最多调用一次模型。相同 operation 重复提交返回原状态，不因刷新再调用。 |
| `GET /expression-plans/{plan_id}` | 只读返回当前状态、可编辑建议和版本；无任何新增派发。 |
| `PATCH /expression-plans/{plan_id}` | 带 `expected_revision` 的标注选择/移除，按相同白名单和区间规则校验，产生新 revision，不调模型、不合成。 |
| `DELETE /expression-plans/{plan_id}` | 取消该计划的等待/后续工作，迟到结果不能发布；已尝试模型计数不返还。 |
| 现有 speech-preview 与 speak | 后续增加可选 `plan_id/plan_revision`，预览返回完整实际文本、基线/标签、语言、逐段字符与请求数、有效参数及新预览指纹。speak 必须带该指纹，后台重查全部绑定；沿用现有普通模式请求的行为。读预览不启动规划。 |

状态分开记录来源资格、规划、合成和播放。规划状态采用 `planning/ready/empty/fallback/failed_unknown/cancelled/stale/restricted`，空计划与失败不是同一状态。`fallback` 仅表示已明确选择的现有普通/规则路径，必须写出 `requested_mode/effective_mode/fallback_reason`，不伪造 AI 成功。

- 正文、归属、完成/展示状态、Profile、告知、模型、有效参数、上下文或规则版本漂移，旧预览返回 409，零规划或 TTS 派发，要求重新预览。
- 明确的结构失败或 20 秒期限到达可结束规划并提示沿既有普通路径朗读；只有已有相应朗读授权且预算足够时才可继续，不能增加原定合成次数。规划结果未知保留占用和可靠 usage，不自动重新规划；界面可保留普通缓存入口。
- 取消、切换、撤权或展示受限直接停止相关规划/合成/队列，不能用回退重新启动旧轮次。完整文字是否可展示仍由原门控决定，不由语气模型判定。
- 新增规划独立计量，复用持久身份、并发预占和预算机制；旧聊天生成、Scribe、HTTP/WS 验收预算不自动转成规划额度。缓存播放免新合成，未知用量和实际账单分别记录，账单未知不填零。

### 3.5 指纹、缓存与最小交互

输入采用版本化、排序键的规范 JSON（UTF-8、无多余空白）计算 SHA-256，保留换行，不做未声明的 Unicode 归一化。输入指纹覆盖来源与资格、过滤/分句版本、安全正文、声音设定及 Profile revision、Voice ID 摘要、规划模型/提示/规则、粒度及实际公开语境/可选快照身份。模型响应必须原样回传该输入指纹。

最终预览和音频键另含计划 revision、用户修订、最终有效表达/标签及完整送读文本、渲染版本、TTS 模型、路径 HTTP/WS、语言、格式和全部有效参数（含省略状态）。只隐藏小标、播放/暂停或刷新不改变计划、不重复规划。显式重新规划使用新 operation，不复用结果未知身份；显式重新生成音频也受原预算与权限约束。旧普通音频和所有旧表达版本继续可访问，不把旧声当成修改后的方案。

现有 `voice_expression_audio` 限制每消息/模式/sequence 唯一且 sequence=0，不能直接覆盖它保存多次编辑结果。第 2 步先使用独立隔离评测存储，绑定 owner、消息版本、plan revision 与音频身份，验证多版本共存；不擅自迁移正式库或扩大现有 CHECK。日常持久方案放到第 4 步执行单，届时列精确差异与备份/回退。

## 4. 第 2 步：AI 语气规划最小版本

### 范围与顺序

### 必要行为

- 开启规划时每条新回复只规划一次；播放、暂停、刷新、缓存重播不自动重复规划或收费生成。

- 记录规划耗时、合成耗时、实际请求与字符数量、缓存命中、失败/未知原因。包含标签的送读字符照实际计数。
- 不因为新增一次规划就重复执行原聊天模型、工具、心理更新或记忆结算。

### 验收

验证正文不改、空计划、少数句标注、段句混用、模型非法 ID/标签、结构错误、超时、权限撤销、旧轮次迟到结果、手工修改后缓存隔离。听评关注阿夜的音色辨识、克制度、语气是否贴合、是否表演过度、额外等待是否可接受。通过范围只写本次文本/模型/设备。
