# Memory V2 Phase M1：原生只读档案

M1 只索引现有 `messages` 与 `activity_operations`。原文权威仍在原表；`mv2_*` 表保存可重建的来源元信息、哈希、词项和时间片段，不保存第二份原文、模型改写或摘要。M1 没有自动任务：索引批次须通过显式维护接口推进。旧聊天注入、Phase 1～6.5、R1/R2 权威检查均不调用 M1。

## 来源与时间

稳定来源引用为 `(source_kind, source_id)`，分别对应 `message:<messages.id>` 和 `activity_operation:<activity_operations.id>`。索引行另含 `character_id` 与索引代；同一代的来源键全局唯一，角色从当前原表重新核对。时间片段 ID 可以重建，不能作为永久来源引用。

- 消息只取 `user`、`assistant` 的可见 `content`。用户正文是用户陈述，助手正文是模型生成内容；均不自动成为已验证事实。`system`、`tool`、工具参数／结果、推理、独白和 Provider 状态不进入词项或展开内容。
- 原生消息 `created_at` 同时记录本地事件与入库时间。历史导入消息的 `occurred_at` 一律未知；存在 `imported_archives` 收据时，其 `imported_at` 是记录时间，否则记录时间也未知。索引时间单独保存。
- 活动操作只展示类别、状态和已知本地环境动作的安全名称。`arguments_json`、`result_json`、外部工具返回和任意未知动作名称不进入词项或展开内容。`created_at` 是记录时间；精确发生时间未知；`updated_at` 是状态记录时间。`unknown` 仍为未知，不升格为成功。
- `content_hash` 使用允许展示的原样正文计算 SHA-256；`state_hash` 使用原始记录及归属字段的规范化 JSON 计算 SHA-256。敏感字段仅在内存中参与状态校验，哈希和词项仍按私人数据保护。

## 索引与 API

### 历史来源顺序契约（隔离实现，正式迁移待批准）

新排序契约为 M1 schema v2。H2 已完成文件必须由导入批次、文件及收据共同证明：文件 SHA-256、解析器版本、角色、单一归档会话一致，收据数量等于文件清单预期数量，`source_ordinal` 为连续的 `1..N` 正整数，且每条收据仍指向同角色、同会话、正文指纹匹配的消息。原文件不在场时，这是**数据库内元数据一致性验证**，不是重新校验原文件字节。未完成、缺收据、重复、越界或跨会话归属不明的文件暂停索引，不用本地 ID 或时间猜测顺序。

已验证文件在文件与会话作用域内按整数 ordinal 排列；不同文件独立成组，文件 ID、文件名和导入先后均不表示发生先后。原生消息及活动的原排序语义保持不变。历史时间间隔只在相邻来源都有经核实的精确 `occurred_at` 时计算；倒退记 `time_order_conflict`，不重排、不取绝对值、不据此切段。未知或未核实时刻不以 `recorded_at` 代替。跨文件连续纪事另需可信同依据的精确时间或人工确认顺序；搜索相关性、M2 排序及 `experienceKey` 去重不采用 ordinal。

搜索与片段分页游标使用域隔离的稳定服务端密钥作 HMAC-SHA256 签名，只包含查询及筛选指纹、角色、索引代、排序版本、索引修订、末位排序键和完整来源快照指纹，不包含聊天正文或搜索原词。每次续页重新校验来源与收据；篡改返回 422，合法但过期返回 409，密钥不可用返回 503。完整快照验证上限为 20,000 个候选来源，超限拒绝续页，不省略验证。

全新隔离数据库可显式初始化 v2；旧库的 `migrate_order_v2()` 是独立显式迁移，**普通 `main.init_db()` 不执行旧库排序升级**。旧索引不可作为有效顺序结果；迁移后状态为 `needs_rebuild`，旧任务游标不能续跑。新索引经来源重新验证后原子切换，失败保留 RAW 与派生数据，不恢复旧错序索引为有效。正式库迁移、备份恢复及启用须另行批准。

`mv2_meta`、`mv2_sources`、`mv2_terms`、`mv2_segments`、`mv2_segment_members`、`mv2_jobs` 是唯一新增表。角色删除级联；迁移幂等。旧备份没有这些表时，恢复后状态为 `needs_rebuild`。运行中的索引任务在初始化或恢复后转为暂停，不能自动重放。

显式维护接口：`POST /api/memory-v2/index/jobs`（`characterId` 与 `mode: rebuild|incremental`），`POST /index/jobs/{id}/step|pause|resume?characterId=...`，`GET /index/jobs/{id}?characterId=...`。每次 step 至多扫描 100 个来源。首次须使用 `rebuild`；后续 `incremental` 每轮扫描来源清单，仅更新发生变化的派生项，并清除失效项。重建写入新索引代，完成后原子切换；未完成时旧代继续服务且逐条验证来源。

只读接口：`GET /api/memory-v2/status`、`/segments`、`/segments/{id}/sources`、`/search`、`/sources/{kind}/{id}`、`/sources/{kind}/{id}/unfold`。均使用现有 owner session 和明确的 `characterId`；内容页不超过 4096 字符，分页上限 50。搜索词以 UTF-8 的 base64url（无填充）编码放在 `X-Memory-Query-B64` 请求头中，避免中文编码错误和查询内容出现在常见 URL 访问日志；该编码不是加密，应用不记录此请求头。搜索以 NFKC、大小写折叠后的拉丁整词和中日文相邻二字词项交集筛选，因此二字专名可查。跨来源相同原样正文仅提示可能重复，不合并来源。

每次 GET 从当前原表重读角色、状态及内容／状态指纹；失配、删除、失权时不返回旧正文、标题、片段成员或检索命中。GET 不触发回填，也不调用 `learning_context()`、心理预览、模型或工具。时间片段按原始对话／活动会话及时间依据分开，以 30 分钟间隔切分，类型明确为 `temporal_segment`；标题只描述发生或记录时间，不声称语义主题。索引代变化使旧分页游标返回 409。M1 API 响应设置 `Cache-Control: no-store`，不持久记录查询词。

增量任务正在重建时间片段或暂停在该阶段时，片段列表和成员读取返回 409，避免把部分重建结果作为完整档案。大量失效来源只影响扫描进度；分页游标仍可继续向后读取。

## M3 预留契约，不在 M1 实现

未来独立派生文本可分别保存 `cleaned`、`narrative`、`digest` 视图，并使用有序来源列表 `(character_id, source_kind, source_id, ordinal, input_fingerprint)`。这些引用必须直达原始来源，不能依赖可重建的 M1 索引行或时间片段 ID。来源编辑、删除、状态或权限变化使派生文本失效；同一来源允许多视图，但正式上下文不能重复注入为多段独立经历。

M3 才评估结构清理、保守的括号翻译去重、阿夜第一人称重述、事实与出处核验、人工修订和周／月／季度摘要。未来管线的顺序为原始来源、结构清理、可选翻译去重、第一人称重述、事实与出处校验、派生持久化、分级摘要。括号内容含新事实、否定、条件、约定或情绪信息时不得被当作重复翻译删除。第一人称可使用符合角色设定的「俺」，但不得把用户发言归给阿夜、虚构情绪或经历，也不得把模型自述升级为已验证事实。派生记录届时需包含规则、提示词、模型版本、内容版本、来源顺序、事实／叙事解释区分及重建状态。活动叙事只可使用授权且安全筛选的事实，不读取隐藏工具载荷。长期偏好和学习结论仍走 Phase 5 审批。精修质量须以真实 Token 用量与原文忠实度测试验证，不能只比较字数。

## 验证与回滚

所有测试先设置独立 `YOSAKI_DATA_DIR`，只使用合成数据和本地模拟服务。正式数据库首次启用前须单独制作并验证加密备份，再在副本上演练升级和恢复。代码回滚可保留未被旧代码使用的派生表；如需删表，必须先校验可恢复备份，只删 `mv2_*`，不触及原始来源。M1 不自动进入 M2/M3。
