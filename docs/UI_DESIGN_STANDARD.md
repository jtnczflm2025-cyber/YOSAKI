# YOSAKI UI 开发基准

版本：银灰玻璃 v1，2026-11-17。适用于所有现有与新增页面、功能窗口、独立阅读页、浮层和移动布局。后续执行窗口在修改 UI 前应阅读本文件，并沿用现有共享组件；产品与数据约束仍以 AGENTS.md、Memory V2 和 Voice 专项规范为准。

## 1. 固定视觉方向

以用户提供的第二张参考图为主：冷银灰、珍珠白、石墨灰，安静、清晰、有留白。背景低细节，透明曲面只用于欢迎和工作台氛围。光效集中在边缘、转角及交互焦点。

禁止大面积高饱和紫蓝渐变、强霓虹、过曝白光、四周彩虹描边、塑料式大光斑、密集仪表盘、无依据的统计数字和重复说明。中文文案简短自然，保持陪伴、探索和私人空间的气质。

## 2. 唯一变量来源

`frontend/src/ui/tokens.css` 定义颜色、阅读字号、行高、间距、圆角和阴影；`silver.css` 管理共享外壳、控件与响应式规则；`theme.ts` 管理全应用及 Chronicle 主题。禁止在功能组件内新增一套浅／深主题或硬编码自己的紫色背景。

| 语义变量 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--ui-bg` | `#E5E8ED` | `#171B21` | 页面底色 |
| `--ui-surface` | `#F8F9FB` | `#232830` | 稳定正文底面 |
| `--ui-raised` | `#EEF1F5` | `#2D333C` | 输入与分组底面 |
| `--ui-ink` | `#242B34` | `#EDF0F4` | 正文与主标题 |
| `--ui-muted` | `#56616E` | `#B4BDC8` | 次要说明 |
| `--ui-line` | `#B5BEC9` | `#697583` | 控件边界 |
| `--ui-primary` | `#303944` | `#DDE3EB` | 主要操作，文字配 `--ui-on-primary` |
| `--ui-accent` | `#536C89` | `#ABC3DF` | 焦点、链接及选择态 |

状态色使用 `--ui-success`、`--ui-warning`、`--ui-danger`，必须同时有文字或图标，不单靠颜色。主题偏好键是 `YOSAKI.ui.theme.v1`，只保存外观偏好。

## 3. 三级玻璃

| 层级 | 用法 | 规则 |
| --- | --- | --- |
| hero | 欢迎页背景与少量悬浮卡 | 通透最强，细亮边、局部折射、低强度色散 |
| navigation | 侧栏、窗口标题栏、工具栏、输入外壳、浮层 | 中等磨砂，边界明确，文字稳定 |
| reading | 聊天、记忆、长说明和编辑正文 | 使用较不透明的 `--ui-surface`；不折射正文 |

使用 `GlassSurface` 的 `level`；`refract` 只给少量关键面板。底面、边框、光效与文字分层，禁止降低含文字容器整体的 opacity。阴影用于分离层次，不叠多层厚边。正文上方不能穿过地球、轨道或背景纹理。

SVG 折射是渐进增强；不支持的环境使用磨砂底面和边框。减少透明效果时使用稳定实底。玻璃动画若以后增加，必须在页面不可见时停止。

## 4. 字体与阅读

- 系统中文字体栈包含 Segoe UI、苹方、微软雅黑和 Noto CJK；日文可用 Yu Gothic、Hiragino、Noto CJK JP。不得只依赖拉丁字体。
- 聊天、精修正文和单经历梗概基准为 **17px / 1.75**。手机保持 17px，不以缩字解决拥挤。
- 长正文列宽上限约 860px；手机优先减少装饰和多层内边距，保留自然换行。中日文禁止整段 `word-break: break-all`，长 URL／连续字符可 `overflow-wrap: anywhere`。
- 控件和普通说明使用 14–15px，辅助信息通常不低于 13px。欢迎标题桌面 32–48px，手机约 32px；功能标题 24–28px。
- 原始换行和段落边界要保留。逐行渲染不能给每个空行再叠加大段距；长文本不得固定截高且不提供展开。
- 代码和宽表格局部横向滚动，不能撑破页面。技术详情与用量按需展开，不占用主阅读区域。
- 不把每条助手消息包进多层玻璃卡。用户消息可有一层低对比稳定底色。

## 5. 布局与导航

欢迎页采用左文右图，地球是视觉中心；主按钮直接进入已有工作台流程。工作台保持稳定侧栏，地球周围固定“对话、记忆、工具”直达卡，其余功能完整保留在分组导航。

桌面侧栏 232px、收起状态 76px；900px 以下为抽屉，600px 以下表单优先单列。常规间距沿用 4、8、12、16、24、32、48、64px。控件／面板／窗口圆角分别以 12／20／28px 为基础。

进入功能后把面积交给内容。完整页面和浮动窗口使用同一个业务组件，不能复制出功能不一致的实现。浮窗标题栏负责拖动，按钮和输入控件不得启动拖动；不使用 scale 表达聚焦而破坏坐标。最小化、最大化、关闭及恢复必须可用，并具有可访问名称。

右侧状态只展示真实的当前角色、当前模型、连接、生成、录音、未保存及错误。没有数据时显示未知、未连接或空状态，不补造数量、速率和“系统健康”结论。窗口列表可以收起，不能变成第二个密集仪表盘。

## 6. 地球交互与生命周期

复用 `YosakiGlobe.vue` 和 `globeScene.ts`，不为页面创建不同版本。地球采用深银灰球体、可辨识大陆点阵、细经纬线、少量轨道和微光节点。轨道是装饰，不对应真实服务器位置、记忆地点或网络流量。

- 拖动旋转、释放后轻微阻尼；空闲时缓慢自转；提供暂停和复位。
- 功能卡是独立 HTML 按钮，文字始终正向，位置不跟随球体。拖动释放后不能误触导航。
- 方向键提供旋转替代操作，焦点可见；手机保留页面纵向滚动。
- 页面隐藏、组件离开视口、浮窗遮盖工作台时停止本组件渲染；卸载清理监听、WebGL 资源及观察器。
- `prefers-reduced-motion: reduce` 下停止自动运动和惯性，仍允许用户主动操作。
- 点阵或 WebGL 失败显示本地静态图，导航独立工作。客户端资源来自本地，不依赖第三方地图请求。
- 不在聊天、记忆正文旁持续挂载大型地球。

## 7. 控件和状态

主要触控目标以 44px 为基准；紧凑桌面控件可更小，但手机不能把关键操作缩成不可点的小图标。所有图标按钮要有可访问名称。键盘焦点使用共享 accent 轮廓；弹窗保持焦点、Escape 取消并恢复触发点。

正在录音、远程识别告知、工具等待确认、执行中、失败、未保存和中断必须有持续可见文字。关闭、切换角色和离开页面不能静默丢失未保存资料。中文／日文 IME 确认候选时的 Enter 不得发送消息；Shift+Enter 保留换行。

加载状态不能伪造为成功；禁用按钮仍要可辨识。金额、模型用量、额度和能力必须来自实际状态，缺失显示“未提供”。视觉调整不得改变同意、授权、计费、来源和数据保护。

## 8. Memory 与 Voice 专项约束

精修正文、单经历梗概、周期摘要分开呈现；阿夜通道仍展开到精修正文，不因 UI 标签或摘要卡而返回 RAW／CLEANED。用户核对来源的入口和权限提示保留。unknown、审核、保存与发布边界不变。

语音页面、消息播放器、录音草稿和通话设置使用同一色板。远程识别告知、开启确认和额度放在明确命名的“语音与通话”面板中，在开始操作前可见，不塞入无名称的“更多”菜单；活动状态、错误和停止按钮持续可见。UI 验收不能替代真实麦克风、供应商、费用和跨设备专项验收。

### 聊天信息层级（全页和浮窗共用）

- 全页保留应用标题和一条紧凑的角色／当前对话工具栏，不重复显示浮窗标题栏；浮窗仍保留拖动、最小化、最大化、关闭和全页切换。
- 默认输入区只保留草稿、发送／停止，以及“语音”“朗读：开／关”“本条补查”等有名称的入口。对话搜索、新建、重命名、删除、导出和批量档案进入“对话管理”。低频设置不持续挤占正文。
- 设备选择、语音额度、开始确认和通话参数在独立滚动抽屉中呈现。抽屉用 `v-show` 保留录音组件；关闭设置不能等同结束录音。活动条在输入区和已打开抽屉的固定底部均提供当前状态、打断／结束／取消操作。
- 抽屉支持 Tab 循环、Escape 关闭、恢复触发焦点；抽屉打开时正文控件 inert。未开始通话时关闭面板，清除开始确认和本次插话选择。
- 付费补查必须逐条明确选择。关闭面板后输入区显示本条选择、费用上限及撤销；发送一次、编辑草稿或切换角色／对话／模型均清除，不静默沿用。额度以实际服务端数据为准。
- 工具待确认／执行中在正文保留原操作卡，并在输入区显示提示；按钮和键盘发送都不能绕开等待状态。错误可用两行摘要加详情，详细原因不可丢弃。
- 验收使用相同能力开关、同一中日文长对话，比较默认阅读、录音、播放、失败／额度不足、工具待确认和浮窗；同时记录正文可视高度、输入区高度、字号、行高及横向溢出，不能只测禁用语音的空页面。当前测量证据见 `design-qa.md` 的聊天层级补验。

## 9. 后续修改的完成条件

1. 先看现有组件与共享变量，修改前核对未提交工作；不编辑 `App.vue.js` 等生成物。
2. 对应功能在浅色、深色、全页和实际使用的浮窗尺寸下可读；手机无页面横向溢出。
3. 同时查看欢迎页和至少一份中日文长正文，不用空白首页作为唯一完成依据。
4. 检查长标题、空状态、加载、错误、禁用、未保存及相关确认流程。
5. 执行类型检查／构建以及与行为变化相关的测试；保留截图和实际验证范围。
6. 新样式优先进入共享语义变量或组件；确需例外时记录用途与视觉证据，不能悄悄新增一套主题。

## 10. 可直接发给后续执行窗口

> 本次开发继续遵守 `docs/UI_DESIGN_STANDARD.md`。所有新增或修改的页面、浮窗、表单、语音控件和状态提示均复用 `frontend/src/ui/tokens.css`、`silver.css` 及共享主题组件，保持冷银灰／珍珠白／石墨灰的三级玻璃体系。正文按 17px、1.75 行高，手机不缩字；底面与文字透明度分离。地球只用于欢迎和导航，隐藏时停动画，失败保留导航。保留全部现有功能及来源、权限、逐次确认、未保存、录音和错误状态。不要新增高饱和渐变、虚构统计或独立主题。完成时验证浅深色、桌面手机、相关浮窗，以及实际中日文长正文，并说明测试和截图证据。Memory V2、Voice 与数据安全仍以各专项规范为准。
