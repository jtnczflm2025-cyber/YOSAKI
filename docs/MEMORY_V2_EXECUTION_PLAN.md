用途：用户、ChatGPT 与本机 Codex 的共同需求基线和交付标准。每轮先读本文件，再持续实施。  
项目内固定位置：`docs/MEMORY_V2_EXECUTION_PLAN.md`。原始1.0模板与下方按日期记录保留；当前交付及资格以本文件已更新的C1～C10总表为准，历史阶段状态不代表最新结果。

> **唯一目标：把原有 Chronicle 记忆能力接成用户能实际使用、阿夜能检索和展开的完整流程。保留既有有效功能，纠正内容视图和产品体验的偏差。不再把每个模块拆成新的请示、研究、准备或演示阶段。**

## 开工必读：不可改变的约定

1. RAW 是保存和追溯的原始证据；阿夜的记忆浮现、主动检索返回和展开入口不得返回未改写 RAW，也不得以 CLEANED 冒充精修正文。用户管理页仍可核对 RAW；加工器可按授权读取来源。此限制针对记忆通道，不禁止正常聊天携带当前对话历史。
2. NARRATIVE 是完整的第一人称精修对话，尽量保留原内容；Synopsis 是单经历梗概；Temporal DIGEST 是周期摘要。三者职责、提示词、字段和验收分开，禁止互相替代。
3. 时间树保持 L0～L5、7／30／90／180／365 天既定边界。近详远略，命中后按档位浮现；旧记忆展开最终到完整精修正文，不到 RAW。完整正文不因折叠而删除。
4. 不擅自筛选、去重、压缩精修对话；不删日文原话；不虚构内心和亲历。只有梗概和周期摘要承担内容压缩。
5. Chronicle、心潮念和 Phase 经验权威分开；不写入心潮念，不冒充阿夜主动笔记，不自动批准 Phase 5 学习。
6. 系统承担加工、索引与维护。不得将开发评测工具变成用户每天逐句填表的工作，也不得借此绕过既有内容使用资格。
7. 本计划范围内连续实施、验证、修复并交付。不要完成一个子项就停下来问“是否继续”。
8. 只报告真实完成状态；源码存在、隔离通过、用户可见、日常启用分别记录。不得以测试数或文档数代替可用功能。

## 固定产品行为

### 单条精修与条目

条目保留稳定身份、日期依据、带时间的标题、分类、标签、关键词、单经历梗概及完整精修正文。分类／标签／检索词不强行合并；未填写字段不能被伪造。原始发生时间未知时标明未知，不用导入时间编造年龄或标题日期。

NARRATIVE 以用户原始《记忆条目编写规则.txt》及前后样例为文体基线：

- 开头可用“イキヤ说”，后文按归属用“她”；有多位女性或引述时用名字消除歧义，不机械替换。
- 阿夜每轮使用“我说：”“我告诉她：”等前缀，尽量保留日文发言本身；引语中的「俺」「お前」不全局改写。
- 删阿夜发言中可确认的中文重复翻译，删大部分装饰性省略号；不能删除含独立事实的括号，也不能把所有停顿和语气都抹掉。
- 保留原轮次先后、细节、反复、更正、否定、条件、未定状态和双方说话归属。只作人称、语法与排版所必需的修改，不重新提炼论点，不添加动作和感受。
- 原话中的事实错误仍作为“她说／我说”的发言记录，不擅自纠正成外部事实，不把旧承诺变成已完成动作。
- 2026-11-18 补充标准。正文由阿夜第一人称承接，イキヤ的发言可自然转述；逐段核对谁在说、谁在做、谁被照顾。存在人物或主客体歧义时使用名字；原话自身仍有歧义时保留归属明确的直接引语。不得机械把“你”替成“我”而交换施事与受事。
- 允许整理口语语气和句式。原话有明确“哈哈哈”等笑声时可写“イキヤ笑了笑”或“イキヤ笑着说”，该授权限于原话可核实的表达。纯语气的“对不对”“你说是不是”可以省略；影响内容或后续答复的问题须保留问意。本地规则不能可靠区分时保留原问句。事实、条件、否定、后续更正、关键细节及原轮次顺序持续保留。
- 允许为了长文本容量分批，但不得遗漏、重复或用各批摘要拼成完整精修正文。正文过长时分页／分块展示，不能静默截断。
- 系统加工能力优先实现有限转换与消息级来源对应，不要求模型生成完整语义图。
- 原始样例是文体与保留范围依据，不是要求每个字节完全复刻；样例里的概括句不能扩展成自由虚构权限。

Synopsis 可概括单条经历；时间 DIGEST 可合并周期内容。二者保留事实、归属、条件和更正，但不适用全文保留要求。原始样例中梗概用“イキヤ／阿夜”，无需强制全部第一人称，也不使用泛化的“用户／助手”替代已知名字。

### 时间树与记忆通道

| 层级 | 既定年龄阈值 | 默认内容 |
|---|---|---|
| L0 | 7 天以内的近期档 | 完整精修纪事 |
| L1 | 7／30 天之间 | 周摘要 |
| L2 | 30／90 天之间 | 月摘要 |
| L3 | 90／180 天之间 | 季度摘要 |
| L4 | 180／365 天之间 | 半年摘要 |
| L5 | 年龄达到 365 天 | 合资格年度摘要；标题保留导航及缺失／不合资格／超预算时降级 |

边界当天的比较符和日历时区沿用既有 P2 契约及测试，不重新猜定；交付中展示边界例子。时间随读取日推进，不靠删除正文实现遗忘。摘要失效／缺失时沿用有效单经历梗概／标题降级；不以 RAW 或 CLEANED 回填。

浮现顺序是检索候选→统一资格和相关性过滤→时间视图与去重预算→上下文。不是整棵时间树常驻。周期摘要只可代表经过候选选择与权限校验的范围，不能因为某条命中而夹带未获准的整个周期。

阿夜主动搜索与被动浮现分开；主动展开不受被动冷却阻止。展开可逐级查看摘要，最终查看对应完整精修正文。精修正文缺失或失效时明确返回状态，不暗中返回 RAW、不在读取时偷偷发模型请求。内部检索可利用授权来源索引，但返回正文、snippet、fallback 和工具响应均须遵守同一视图约束。

普通浮现与常驻记忆独立：重要性、奠基性质、Permanent、用户固定参考不能混成一个分数。由明确授权主体作决定，系统不得凭情绪或相似度自动赋值。提供基本设置、取消、理由及持久化，不要求新的复杂评分体系。

### 自动整理与人工质量确认

复用任务系统完成已授权来源的加工、增量索引、失效重建和周期摘要维护；新增／变更后可继续工作，不要求用户逐字段点火。不在 GET 中产生模型费用，不因重启重复派发，不绕过 unknown。

**现有 M3 要求人工质量确认，这是历史明确契约，不在本计划中悄悄删除。** 产品先实现正常正文阅读、按条或按选定条目批量明确确认与纠错，不新增逐句勾选证据、手工命题图或隔离评审身份步骤。批量操作仍逐条绑定具体版本和来源，不得批准未包含在本次操作中的新内容。系统自动准备内容、用户确认内容资格是两个不同动作。

不把“自动加工”宣传成“模型输出自动成为可靠记忆”。若现有契约使自动日常使用无法实现，Codex 必须在同一执行任务内指出具体条款和实际影响、提出最小政策差异，集中交用户作一次明确决定；不得先放行，也不得为此停止其余可完成工作。不能以改进用户体验为名伪造审核人或自动授予审核资格。

### 页面与使用

在既有 YOSAKI／Chronicle 入口交付，不再另造常驻的 localhost 演示站作为成品。默认可读正文与日期／标题导航；梗概、完整记忆和原始对话命名明确。用户可以搜索、展开、修正、确认及管理来源，刷新后状态保留。

点击“查看原始对话”才展示 RAW 对照；这是用户管理操作，不是阿夜工具能力。技术状态和模拟按钮在开发详情中。意见／修改保存后直接显示成功，切换时保存草稿或明确提示，不无声丢失输入。界面说明“会记住什么、为何尚不可用、操作后发生什么”，不要求用户读哈希、命题关系或内部错误码。

## 保留、停止与不纳入此次收口的边界

**保留并接通：** 来源及导入、稳定条目、自动元数据、精修、梗概、周期摘要、时间树、关键词／向量／Hybrid、相关记忆、普通浮现、主动展开、基本策展／常驻、年历管理、版本失效维护、任务恢复、现有备份能力。已有组件优先复用。

**停止继续建设：** 新命题图协议、通用自然语言证明器、逐词特例竞赛、全量逐句人工证据平台、新独立评审应用、与本次目标无关的重构和重复研究报告。保留历史实验、费用、失败与诊断，不破坏已有数据。

**保留为原路线中的后续独立能力，不作为本次 Chronicle 收口前置条件，也不能称为“一开始不需要”：** M4 与 Phase 1～6.5 的完整经验桥、心潮念授权连接器、独立 AI Scheduler／AI 日程表、高级策展与关系分析、缓存命中专项优化、VPS／多机部署。基本记忆维护任务和基本个人策展仍属本次范围，不能借此延期。

本次交付的准确名称是“Chronicle 记忆主流程完成并可日常使用”，不能宣称所有未来记忆愿景都已实现；也不能把关键词降级或单个摘要原型包装成完整 Chronicle。
