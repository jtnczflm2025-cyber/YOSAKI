## 埋点与期限审阅

- CONNECT由httpcore请求method区分，代理200不冒充目标200；TLS开始／完成单列。目标POST开始才解除外层连接总预算。代理TCP、CONNECT和目标TLS均包含在该连接预算中；不是所有代理内部行为都有单独事件。
- `send_body_complete`只说明客户端本地发送返回。没有供应商接收确认，不能据此证明对方已接收或处理全部正文。
- `transport_headers_complete(hop=origin)`是底层HTTP解析器事件；`response_object_ready`是`client.send(stream=True)`返回控制权。二者分别记录，即使本次被四舍五入到同一时间，也不能说二者在语义上相同。
- 首响应60秒的外层计时在调用`client.send`之前开始，**包含连接与请求发送**，不是从`headers_wait`开始另等60秒。连接预算在POST头开始时解除；HTTP硬限从客户端构建前开始；执行层和任务期限是更外层限制。保持原值和既有语义，未调整。
- 仅在目标200响应返回后进入`aiter_bytes`；每次等待下一个解码后音频块受读取空闲30秒限制，同时始终受HTTP硬限约束。收到错误状态先拒绝，不把错误正文当音频；未知的错误详情不落日志。
- 现有诊断不记录代理出口、上游排队、原始网络帧／响应头和错误全文，无法区分这些内部原因。目标无头时不会生成HTTP状态，也不能据超时认定收到某种供应商错误。
