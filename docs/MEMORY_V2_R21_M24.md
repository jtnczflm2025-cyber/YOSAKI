## 最小 schema 与生命周期

`messages` 的工具助手批次新增三个可空字段：

| 字段 | 含义 |
| --- | --- |
| `origin_user_message_id INTEGER` | 首次请求写入的原用户消息稳定 ID。消息使用 SQLite `AUTOINCREMENT`，删除后不复用。 |
| `origin_user_content_sha256 TEXT` | 原用户正文 UTF-8 字节的 SHA-256；用于检测编辑和错误绑定。 |
| `origin_character_id INTEGER` | 创建批次时的角色 ID；与对话当前角色再次比对。 |

`init_db()` 对旧表幂等补列；没有回填旧批次，也没有更改用户消息、原始证据或 M1 表。字段不设到用户消息的级联外键，以便删除来源后保留批次诊断，继续时显式拒绝。原对话外键仍负责消息生命周期。已完成的旧工具历史继续展示；旧待继续批次因锚点为空而返回 409，不能按剩余消息推断或自动补全。角色删除沿用现有工具运行清理，消息随对话删除。

首次 `/api/chat/stream` 保存或重新生成复用原用户消息 ID，计算正文指纹。若模型提出工具调用，在 `BEGIN IMMEDIATE` 事务中重新核对原消息仍属于同角色、同会话、正文未变且没有新的消息，然后一起写入携锚点的助手批次与所有工具运行；事务提交后才向客户端宣告待确认。后续 `/api/chat/tool-runs/{id}/continue` 在改变状态前验证该锚点、完整助手／工具结果链和调用 ID，用 SQLite 原子状态更新占用批次。新批次在同一事务中再次验证链、继承相同锚点，并完成前一批。发起 Provider 流前另做一次校验；来源失效时输出错误，不发起模型请求，批次回到待继续状态。对话、角色删除，重新生成以及插入新用户消息在批次 `continuing` 时返回 409。

当前应用写入路径与 `BEGIN IMMEDIATE` 提供单进程及多连接的原子占用。直接绕过应用改写 SQLite 不属于产品 API；若在最后一次校验后、网络请求开始的极短窗口由外部进程直接改库，不能撤销已发出的请求。正式部署前应确保没有并行的外部数据库写入者，并在真实部署拓扑中再做竞争验收。
