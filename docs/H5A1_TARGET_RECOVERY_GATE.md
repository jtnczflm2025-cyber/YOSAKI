四种哈希不可混称：①原活动 SQLite 文件 SHA-256 只用于确认源文件本轮未被改动；②在线备份所得的脱敏前快照有独立文件布局，可能与原库字节不同；③V2 manifest 的 `database_sha256` 对应**凭据剔除并 VACUUM 后**的快照；④认证恢复后的 SQLite 在首次应用打开前与③一致。合成演练中①≠②、②≠③、③=④；不能称④为原活动库逐字节副本。首次登录和初始化可能继续修改恢复副本。

## 工作目录、故障与生命周期

【已复现】Python 在本机新建 `mode=0o700` 的 H5 工作目录，Windows ACL 继承关闭，仅 owner、SYSTEM 和 Administrators 有 FullControl。**已有目录不会被 `_work_dir()` 收紧 ACL**：在隔离目录中预先建立的宽权限目录，调用后仍保留继承的额外读取组。因此正式配置的 `YOSAKI_BACKUP_WORK_DIR` 必须预建并验收 ACL，或由代码显式拒绝宽权限目录；本轮不把默认新建目录的结果推广到所有目标路径。

【已复现】子进程在带 H5 标记的明文临时目录写入合成内容后强制退出。立即重新进入时目录保留；将其时间调至超过 24 小时后，仅带标记目录被清理。磁盘空闲量模拟为零时，`create_backup()` 返回 `insufficient_space`，没有发布目标文件。未在目标卷实际填满磁盘；突然断电、文件系统崩溃和安全擦除仍待目标环境演练。普通删除不能保证明文残迹不可恢复，工作目录须位于受保护的加密卷。

首轮**演练脚本自身**未关闭 SQLite 句柄，导致该次合成临时目录清理失败；修正句柄关闭后独立恢复演练通过。针对首轮残留目录的递归清理命令被本地安全策略拒绝，因此该目录仍可能留在系统临时目录；其中只有合成测试数据，不含正式数据。它不属于 H5 工作目录的自动清理范围，需由具备权限的本机维护流程核对并清理。

【源码核查＋已复现】Phase 6.5 测试夹具补充的 `feedback_service.resume_after_restore()` 只修复测试间共享应用状态：前置测试调用 shutdown 后，反馈服务被暂停；单独运行测试则从未暂停。隔离探测还发现，同一进程先 pause/shutdown 再调用 startup，当前 `start_feedback_worker()` 不会自动将 `paused` 置回 False。正常新进程初始为 False。未来任何同进程恢复/重启设计必须显式恢复反馈扫描器并验证事件不会重复入账；不能用夹具通过替代该验收。

## V2 API 边界

【已复现】实际 `main.py` 中间件下，无 owner session 的准备与上传验证为 401；不同登录 session 不能使用他人的下载票据；下载票据单次使用且过期返回 404。准备、下载和验证均为 `no-store`；隔离上传恢复不替换活动库；缩小测试文件上限后超限返回 413。票据默认有效 600 秒，过期清理由后续请求触发。

【源码核查，正式阻塞】`backup_v2_api.py` 只有进程内票据字典和字典锁；没有跨 worker 共享、每 owner 并发配额、全局磁盘配额或长任务截止时间。多 worker 的准备请求与下载请求落在不同进程时，后者无法取得票据。上传大小在 FastAPI 完成 multipart 解析后才由处理函数按块检查，未见 ASGI／反向代理层的请求体总量和连接超时门槛。`prepare` 可同时创建多个大快照；`verify` 可同时占用多个上传、解密和恢复工作区。正式启用前须补齐或用已验证的单 worker、反向代理限额、请求排队及超时方案约束，随后实际并发验收。

## 16 GiB 声明及空间预算

【源码核查】`MAX_DATABASE` 与 `MAX_BACKUP` 均为 16 GiB。单次 AES-GCM 的认证范围涵盖文件头 AAD 和全部压缩密文，只有 `finalize()` 成功后才解压候选；这符合 [cryptography 的 GCM 使用要求](https://cryptography.io/en/stable/hazmat/primitives/symmetric-encryption/)。[NIST SP 800-38D](https://csrc.nist.gov/pubs/sp/800/38/d/final) 的单次 GCM 明文长度上限高于此格式的 16 GiB 文件限制，因此**算法长度边界并非当前较小档位的阻塞**。这不等于 16 GiB 已经完成性能、空间或故障验收。

【待验证／正式阻塞】最大已测合成 SQLite 仅 768 MiB。16 GiB 原库可能产生接近上限的加密文件；两者使用相同上限，没有对压缩开销及 manifest 留明确容量余量。创建时工作目录与目标目录分别预检空间，同卷时未预留其**合计**峰值；验证上传与认证前解密的全部空间也没有一次性配额。实际额外空间包含在线快照、未发布密文、认证前压缩数据、候选 SQLite 和独立恢复副本。16 GiB 的内存上界、磁盘峰值、总耗时、并发及故障恢复均未实测，不能由 768 MiB 数据线性外推。正式容量应以目标卷实测和保守预留重新确定，必要时降低公开上限或修订容量检查。

## 正式恢复与 H5-B 门槛

整库备份代表一个历史时点。**不得**将其默认覆盖活动数据库，因为备份后新增聊天、人工/批准记忆、活动、反馈与学习会丢失。正式事故恢复须先冻结写入、分别保全当前库与备份、核对来源/角色/版本和备份后新增记录，再提出逐来源合并或明确的数据损失处置方案并单独审批；当前 H5-A 仅支持恢复到新目录。
