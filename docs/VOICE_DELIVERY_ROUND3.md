## 按钮打断

- 对话 11 的历史失败仍是：生成中按钮打断后第二轮因通话游标返回 409，未派发第二次模型；不能追认为成功。修复只在确认同一通话已保存用户消息及 `stopped` 助手消息后推进游标，下一轮上下文排除半截助手内容；前端在非 2xx 时结束通话并清空播放状态。

- 隔离浏览器中假 TTD 两轮完成音频接收及播放排空。首次暴露重复 `completed` 回调导致第二次 `playback-drained` 报 409；已在 `frontend/src/voice/realtimeOutput.ts` 使播放器完成通知幂等，并在 `frontend/src/App.vue` 于 await 前预占通话／轮次／消息的排空通知。复测两轮均播放结束，无 409。`tests/test_realtime_player_completion.cjs` 与受影响 Python 27/27、`npm run build` 通过。此为合成音频与假供应商浏览器证据。
- 插话隔离浏览器使用合成音量输入和约 5 秒假 PCM：触发后约 0.47 秒即预占下一条 Scribe，早于旧播放应结束；同一采集流交给假 Scribe，两轮各只提交一次，未出现额外消息或模型派发。末轮又因持续合成音量触发而命中隔离额度，说明该模拟不能证明真实回声区分可靠。`tests/test_local_barge_monitor.cjs` 补充了 9,600 样本准确移交和单次 claim 断言。真实耳机插话与扬声器回声均未验收，日常开关继续关闭。

## 当前用户操作

在 `http://127.0.0.1:5173/hub?window=chat` 选择阿夜和目标对话，麦克风设备选 UGREEN USB。需要录音草稿时点击“开始录音”，核对文字后手动发送；需要连续通话时勾选“最终转写会自动发送”，查看页面给出的可用轮数，再点击“开始通话”。每次等“正在听取；现在可以说话”才开口。通话中“打断”用于停止当前生成或播放并准备下一轮，“结束通话”释放麦克风及播放器。原对话中若显示回复未完成，使用“手动继续上一条回复（会调用模型）”，不会自动重发。语音页面的“每日自动朗读额度”“Scribe 麦克风草稿”可设置持续日额；聊天页的“设置每通话限制”控制单通话轮数、时长、请求和字符，须显式确认提高，所有限制同时生效。
