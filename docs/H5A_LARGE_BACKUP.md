# H5-A 大容量备份与隔离恢复（隔离工程阶段）

## 启用边界

H5-A 代码默认关闭；只有隔离测试显式设置 `YOSAKI_H5A_ENABLED=1` 才开放 V2 准备、下载和验证 API。本阶段没有迁移正式数据库，也没有批准将备份恢复结果切换为活动数据。旧 `/api/system/backup/import` 返回 409，不能再直接覆盖活动数据库。

V2 文件仅需备份文件及用户另行保存的备份密码即可在另一台受信机器解密；不依赖原电脑 `.secret_key`。恢复后的模型 API Key、MCP 凭据、ChatGPT 套餐授权及登录 session 均需重新配置或授权。密码不能随文件保存在同一处。

## V2 文件格式与认证边界

- 文件头：ASCII `YOSAKI-ENCRYPTED-BACKUP-V2\n`、2 字节大端 JSON 头长度（最多 2048 字节）、规范 JSON 头。头只含版本、`PBKDF2-HMAC-SHA256`／600000 次、16 字节随机 salt、`AES-256-GCM`、12 字节随机 nonce 和 `zlib` 标识。
- 头全部作为 AES-GCM AAD。载荷是**一次** AES-GCM 加密的 zlib 流；尾部为 16 字节认证标签。未使用自行设计的逐块密钥或逐块认证协议。加密前的流为 4 字节 manifest 长度、加密 manifest JSON 和 SQLite 文件字节。manifest 包含快照 SHA-256、大小、schema SHA-256、实际存在的表及行数、导出时间与脱敏标记，不含正文。
- 解密先把压缩明文写入受保护的临时目录；只有完整文件 GCM 标签通过后才解压为候选 SQLite。候选再次通过长度、SHA-256、表清单、`integrity_check`、`foreign_key_check`、owner 数和来源收据检查，随后复制到**新建的空目录**并复核。认证失败、中断或校验失败的候选不得发布。
- KDF 参数只接受上述固定值；salt、nonce 长度和头字段严格验证。文件及数据库默认最高 16 GiB，按更大规模调整格式前需重新审查 GCM 边界。错误密码、篡改、调换块、追加、截断和异常压缩内容均拒绝。nonce 每次由操作系统随机数生成。

## 包含、排除与恢复后检查

在线 SQLite 快照包含库中**实际存在**的所有表：原始消息、活动记录、导入批次及收据、M1 索引、P1-A 条目、M3 版本和审核、P2 摘要绑定及应用配置。索引作为可重建派生数据保留在副本中，但恢复后仍须按源指纹、角色和权限重新校验；旧的过期索引不能因恢复而变成有效证据。表不在源库时，manifest 如实记录缺失，不能声称该阶段已正式安装。

仅在**快照副本**中删除活动 session、登录失败记录、模型 API Key 和 MCP secret／session ID，并以 `VACUUM` 消除最终文件空闲页中的旧值。源库不被脱敏操作写入。外部 `.secret_key`、`.chatgpt_plan`、备份密码、环境变量、外部备份目录、浏览器 localStorage 偏好和外部服务数据不属于 `.ybackup`；其中凭据必须单独重新配置，不能混入普通备份。用户自己保存的历史原文件仍需自行保管。

临时明文快照与解密候选可能存在于 H5 工作目录；正式启用前须确认该目录仅 owner 可访问、位于受保护加密卷、有足够空间，并承认普通文件删除不等于安全擦除。操作异常时清理本次临时目录；崩溃遗留目录仅在超过 24 小时、位于专用目录内且含 H5 标记时自动清理，不删除未标记的用户档案。普通日志只记录非正文的状态码与阶段，不记录密码、私人文本、解密材料或完整异常对象。

## 安全恢复路径

对 V1 或 V2 文件使用：

```powershell
python scripts/restore_backup_isolated.py --backup <备份文件> --target <全新空目录> --work-dir <受保护临时目录>
```

H5-A2 起，`--target` 必须是已验证受保护 `--work-dir` 的**直接子目录**，且该子目录尚不存在；工作目录的 ACL 或加密卷状态不可验证时脚本拒绝恢复。

脚本交互遮蔽输入密码，不接受命令行密码参数，也不导入 `main.py`。浏览器的“验证加密备份”只在服务器临时目录完成同样的隔离恢复并返回校验摘要，不切换正式库。目标目录存在即拒绝。旧 V1 通过独立恢复验证后，可在隔离实例中再导出 V2；不会原地修改旧文件。

自动整库回退会覆盖备份后新增数据，因此不提供活动数据库直接替换。未来正式切换、增量合并和损坏库处置需要另行审核。V2 备份必须验证成功后才进入保留队列；失败备份或失败恢复不删除旧 V1 和已验证 V2。大于 64 MiB 的 V2 不通过现有 GitHub Contents API 上传，不能把该云端路径视为大容量保障。
