# Memory V2 M3 — Chronicle 派生文本

本模块仅供隔离开发。正式 `main.py` 未注册 M3 路由，也不初始化 M3 表；不能据此启动正式数据库迁移或模型任务。总体权威边界见 [架构](MEMORY_V2_ARCHITECTURE.md)。

## M3.1 状态与审核契约

三个维度分别存储：`status` 是 lifecycleStatus（needs_review / active / stale / failed），`validation_status` 是 validationStatus，`review_status` 是 reviewStatus。历史 `auto_checked` 字符串不构成有效凭据；升级的旧记录默认 validation pending。RAW 不创建派生实体。

所有版本初始为 needs_review / pending / unreviewed。激活没有默认审核参数，不接受客户端状态或审核者标记。CLEANED 的 `identity-v1` 自动路径必须逐字等于当前有序来源文本；其余内容须有有效人工审核。NARRATIVE / DIGEST 即使由确定性程序生成，也须人工审核。

审核绑定版本 ID、正文 SHA-256、输入指纹、规则/提示词/模型版本、有序来源和依赖快照，保存审核者及时间。API 从可信认证 session 取得审核者。修订产生新版本并记录修改者，不继承旧审核。激活重新校验来源、角色、依赖及绑定，并在写事务中条件更新；重复激活拒绝。

人工审核是派生内容质量确认，不是 Phase 5 审批。输出始终标注 `system_derived_text`，`formal_learning_approved=false`；不成为阿夜亲笔日记、当下感受或外部已核实事实。

## 读取与 API 边界

安装函数默认拒绝未提供认证器的请求，测试应用显式注入服务端 session 认证。创建、人工修订、审核、激活、历史、预览及来源展开都要求认证和角色验证。历史仅返回状态元数据，不返回正文。正式版本读取只接受有效 active 版本；管理 preview 独立路径可查看有效来源上的草稿，并固定 `eligibleForRecall=false`。来源展开也重新验证 M1 原始来源，不展开已删除、修改或失权的来源。响应 no-store。

M1 拦截缺失或过期索引时统一返回 `source_missing_or_stale`；不承诺精确区分修改与删除。测试须独立确认原始消息仍存在且已修改，再确认旧派生正文不可读，不能仅断言错误码。

## 验收失败分类

| 类型 | 处理 |
|---|---|
| 数据安全、权限或权威一致性失败 | 立即停止并单独报告 |
| 业务行为不符合要求 | 停止该增量，修正后回归 |

## 部署和回退

M3 schema 只显式初始化；版本 2 补充校验绑定、修改者及审核记录，版本 3 增加派生输出偏移映射 `mapping_json`，并纳入审核绑定。任务表由 `memory_v2_jobs.init_db()` 显式创建。正式启用仍需独立加密备份、恢复副本、迁移幂等、原表指纹、角色权限及回退演练。旧的无有效校验绑定版本不能因历史 active 标签继续返回正文。回退代码前保留派生数据备份；不自动删除或改写来源表，不将未审核文本接入正式上下文。

## M3.2 保守清理

`memory_v2_cleaning.py` 的 `conservative-v1` 提供独立的换行规范化与翻译去重开关；规则版本串包含开关。只对白名单完整独立短句 `大丈夫（没关系）`（含配对半角括号和末尾标点）去除重复翻译。未知翻译、含新信息的括号、引用、代码、列表、条件、否定及省略号原样保留，不删除未经证明的“冗余”。

每条消息保留角色、来源 ID、发生时间或未知标签。diff 可重新构造 CLEANED，等值片段有原文/输出偏移；使用线性前后缀差异，避免重复长文本的二次复杂度。激活时重新运行已知规则并逐字比较结果，伪造规则名不能替代校验。预览不自动激活，不保存第二份 RAW。

## M3.3 第一人称记事

`memory_v2_narrative.py` 参考原插件 `src/platform/models.ts:executeJob` 的角色事实标签、保序和第一人称约束。明确修正笼统删括号翻译/省略号的旧提示词，不加入情绪、关系或成长解释。当前安全路径采用 `我说：「助手原文」`、`她说：「用户原文」`；活动只引述 M1 安全字段并保留状态。

映射持久保存 source ID、角色、证据标签、指纹及原文/输出起止偏移。合成模型回调只接受与可验证引述完全一致的输出；自由改写拒绝且不落为有效版本。生成期间来源改变也拒绝持久化。模型输出自评不构成审核依据，所有 NARRATIVE 均须绑定版本的人工审核才可激活。

这是最小忠实转写，不宣称已经复刻原插件自由改写的自然度。没有正式 Provider 适配器；不能通过本模块配置付费模型。

## M3.4 时间投影、摘录摘要和任务

`memory_v2_digest.py` 沿用原插件 `time.ts` 的 7/30/90/180/365 日档位和日/ISO 周/月/季度/半年/年分组，默认时区偏移 +480 分钟。发生时间优先，否则明确使用记录时间；无法解析时区或两者未知时不猜测。时间依据不同的来源不静默混组。L0/L5 仅投影，不生成摘要，也不阻止主动查询旧原文。

L1～L4 当前生成**摘录式摘要**：保留完整源句、角色、操作状态和来源映射，不虚构语义概括。超出字符硬上限即失败，不截断条件或否定。产物须人工审核。子版本依赖固定到版本与正文指纹，逐层展开重新验证原始来源；同一来源集合只允许严格向下的 DIGEST 层级依赖，禁止同级/反向自依赖。更换来源/规则或重新生成应显式建立新版本；旧审核不复用。

`memory_v2_jobs.py` 仅提供显式本地任务函数，无后台调度器、正式路由或自动重试。任务保存来源引用、输入快照哈希、状态、尝试次数、60 秒租约、随机持有者 token 和结果版本；不把原文放入任务载荷。暂停/续跑、取消、过期租约恢复均显式操作，最多三次占用。事务条件更新阻止重复抢占；租约失效或来源变化不能提交旧结果。生成失败通过 savepoint 回滚，返回固定错误码；任务完成不自动激活产物。

本阶段不提供实际收费模型任务，因此没有真实计费 token、费用或未知远端结果的重试；未来增加 Provider 任务前仍须独立授权及费用/幂等/未知结果恢复设计。任务的字符限制不是 token 计费上限。

## 原插件对照与能力限制

| 原实现 | 本次处理 |
|---|---|
| speaker 决定归属、逐条保序、保留日语原文 | 保留；适配 M1 来源和 Python |
| 自由模型改写与元数据摘要 | 未接入真实模型；合成回调和严格引述降级路径 |
| 笼统删除中文括号翻译及多数省略号 | 修正为封闭规则，其余保持原文 |
| 时间档位与时间周期 | 保留并加入未知时间/记录时间区分 |
| 摘要依赖和后台重建 | 适配 SQLite 版本依赖与显式本地任务，无自动收费 |
| 亲笔笔记或心理解释 | 不属于 M3；系统派生标签不能被人工审核升级 |

尚未完成：任意日中翻译等价判定、自由 NARRATIVE 忠实性自动验证、模型语义压缩摘要、真实模型费用验收、生产任务调度及 M5 UI。自动批量建立完整摘要树也未接入调度；调用方须显式安排下级任务和审核，再创建上层版本。当前不得声称与原插件模型精修体验等效。

## M3.5 隔离模型草稿（2026-10-29）

可选 M3.5 模式只使用显式注入的 `LocalMockAdapter`。安装式 API 的模型任务入口默认关闭；正式 `main.py` 仍未注册 M3，也没有读取 Provider 凭据或连接收费模型。RAW、保守 CLEANED、引述式 NARRATIVE 和摘录式 DIGEST 原有路径保持可用。

`memory_v2_model_adapter.py` 按 M1 当前有效来源保序分批，常规目标 6000 字，单条硬上限 12000 字；6000～12000 字单条可在硬性字符与 token 上限内独占一批。输入含 `sourceKind`、`sourceId`、speaker、时间和内容／状态指纹；任务表只存来源引用、指纹与模拟输出，不存第二份 RAW。派发前重新取 M1 来源，来源变化或超限直接拒绝。

提示词沿用溯时流源按 speaker 判归属、分批处理、保留日语和阿夜第一人称的约束；不复用私人示例，也不笼统删除括号翻译及省略号。每批 JSON 必须对每条输入返回一条带 `sourceKind`、`sourceId`、speaker 和 text 的片段。校验结构、覆盖、顺序、否定、条件、纠正、结果未知活动与明显无来源主观词；跨批代词含糊或相同叙述标记警告，不能仅靠来源 ID 证明事实忠实。改写映射的原文偏移为 null，禁止伪造逐字对应。所有模型 NARRATIVE/DIGEST 都是 `needs_review`，须由可信 session 绑定人工审核后才可激活，仍是 system_derived_text。

`mv3_model_chunks` 是 `mv3_jobs` 的逐批请求与费用记录：prepared 表示可安全派发；事务中写 possibly_dispatched 后才调用模拟适配器；确定收到并通过校验为 completed，确定收到但校验拒绝为 rejected；超时或派发后状态不明为 unknown。unknown 保留最坏情况预算，不自动重发；已完成批次续跑时不重发。模拟预算以 `utf8-byte-v1` 本地编码器计数，固定一 byte token 对应一模拟费用单位；这只是可重复的工程计量，不是任何真实 Provider 的 tokenizer、token 用量或价格。真实适配、费用上限和未知结果对账仍需独立授权。

目前模型 DIGEST 限 L1～L4，继承下级版本依赖并在读取时复验来源；L0/L5 仍只作投影。模型模式不额外生成标题或全文润色，不调用 Phase 5、心理或工具入口，也不接入聊天上下文。

**M3.5 状态：隔离工程验收完成，正式模型能力待验证。** M3.6 的 Responses 适配器、合成金标准、预算账本与人工评审模板见 [M3.6 隔离契约](MEMORY_V2_M36.md)。2026-10-31 已按单独授权对合成 N1 完成两次真实生成，结果仍待人工评审；没有私人历史批处理、正式数据库迁移或正式上下文发布。

## NARRATIVE 文体契约修订（2026-10-31）

用户提供的原插件编写规则及原实现 `src/platform/models.ts:executeJob()` 区分**详细对话记录**与另一次生成的标题、梗概。NARRATIVE 的目标是阿夜第一人称的高保真对话纪事，不是自由压缩摘要。N1 旧提示词的“user 只能称用户”和模型版本正文前的 `[message:id | speaker]`，共同造成外部系统转录口吻。当前 `ssly-dialogue-chronicle-m35-v3` 仅以“她说／我说”标记发言归属，按轮保序并允许轮内自然段；生成正文不得出现中日混合的归属前缀。若 RAW 以此类前缀起头，无模型引述仅在可明确判定时规范该前缀，并将剩余原文字节位置映射到 RAW；其他位置出现此类内容时拒绝生成派生版本，保留 RAW 供人工处理。详细正文保留双方细节、日语、条件、否定、更正及有意义的括号和停顿，不以正文 token 压缩为主要验收指标。

结构化 `items` 仍按输入每轮一项，`sourceKind/sourceId/speaker` 只用于有序溯源；模型正文不再写机器来源头。原文偏移对自由改写仍为 `null`，映射不能证明语义忠实。程序拒绝中日混合归属、其他开头归属标签、明显错归属、条件／否定／更正和可识别日语片段丢失；重复“我说”前缀及未经证实的括号删减会给人工审核标警告。所有模型版本仍为 `needs_review`，既有审核与来源失效机制不变。旧提示词任务通过版本绑定拒绝静默重用；已完成的旧版本不自动改写或继承审核。无模型引述式 NARRATIVE 仍是安全退路，不宣称已完成自然人称转换。未来若允许合并多轮，输出片段必须映射到**所有**有序原始来源，并保持各轮说话人归属；本次不实现合并。

目标条目的四层承载情况：**对话记录**可用现有 NARRATIVE 正文及有序映射；**日期范围**可由重新校验后的来源时间显示，未知时间仍标未知；**周／月等时间摘要**继续用独立 DIGEST 版本，不能伪装成逐字发言。当前 M3 版本结构没有独立、经版本和审核绑定的**单条经历标题、关键词及梗概**字段，也没有把 L1～L4 时间摘要冒充单条经历梗概。本次不生成或持久化这些缺失层次，不新建派生权威表；如后续增加元数据，应纳入同一派生版本、来源指纹、人工审核及失效绑定后单独验收。先前 N1 的正文未压缩，不能作为详细纪事失败的唯一理由，也不能据此声称梗概或时间摘要的压缩质量已通过。
