# Phase 6.5：整合测试与行为观察

本阶段不增加自动唤醒。行为指标只用于定位异常趋势，不能作为角色任务完成率或真实心理状态的证明。7 天真实模型观察必须按香港日期逐日手动进行；模拟运行不计作真实观察日。

## 已实现的链路加固

- `psychology-v2` 的操作评价不再由 `succeeded` 推出目标进展。没有独立目标证据时 `perceivedProgress=null`；旧 `psychological_events` 保存原评价和规则版本，不回填或重算。确定性衰减、局部事件增量和两层关系传播已与 SQLite 写入分离；事件、快照仍在同一事务保存。
- 启用中的心理关系最多 40 条，审批时阻止超额。传播不再静默截断关系或路径；单边、单目标和驱力参考限幅沿用 Phase 6。操作 `operation:{id}`、反馈 `feedback:{id}`、学习来源事件分别有稳定 ID。操作只记模拟身体负荷，确认反馈才记短期情绪；已批准学习变更只登记来源，不再把同一体验重复入账。
- Phase 2／3 选中的普通长期记忆按 `memories.id` 排除同一条已接受学习记忆的再次注入。`GET /api/desires/{角色}/behavior/context-preview?mode=free|volition&topic=...&includeMemoryContext=false` 返回所选驱力、记忆、学习与心理参考的来源 ID、选取原因和长度；Phase 2 的 `includeMemoryContext` 与实际请求保持一致，Phase 3 总是读取最近记忆。预览不授予行动权限。

## 报告与预算

- `GET /api/desires/{角色}/behavior/report?days=7` 查询 1～31 个香港日。`GET .../behavior/export?days=7&format=json|csv` 导出同一范围。导出不含原始提示词、模型回复、API/MCP 密钥或 OAuth 文件。心理状态全页和浮窗展示每日会话、缺口、已知用量、资源样本、指标和诊断提示。
- `behavior_model_calls` 保存来源、用途、会话、调用状态、耗时、预留输出 token 和供应商返回的可信实际输出 token。缺失可靠用量时实际值保持 `null`。覆盖 Phase 2 观察和纯意愿、Phase 3 自由活动判断、Phase 4 体验回顾、Phase 6 情境评价；普通聊天和旧单步唤醒不属于这份观察调用统计。
- 仅在隔离实例设置 `YOSAKI_OBSERVATION_MODE=1` 时，上述入口共享同角色香港日 **4 次调用**上限；失败尝试也占一次，防止隐式重试。自由活动仍有自身时长、模型、工具及 token 上限。该开关不对普通聊天或旧单步唤醒限额，七天观察请只使用列出的入口。
- `behavior_resource_samples` 在自由活动会话结束、体验回顾完成及反馈应用／跳过后更新 SQLite 分配字节数和关键表行数。SQLite 字节数是整个隔离数据库的页大小，不是单角色精确占用。
- 比率一律带分子、分母和样本不足标记；目标连续率指不同会话重复引用同一持续意愿，活动重复率指相邻实际行动选择同一动作，主动放弃含自由活动拒绝和纯意愿拒绝，另列无效模型输出、已有目标关联及冲突选择分布。预警只提示人工查看：不同情境下连续四次相同动作、高模拟精力下连续五次休息／不行动、无效输出比例升高、数据库增长与心理事件增长失衡。没有自动驱力或偏好调节。

## 隔离副本与逐日观察

1. 停止正式后端，然后运行 `.\.venv\Scripts\python.exe scripts\prepare_phase65_observation.py`。脚本通过 SQLite 一致性备份创建忽略的 `data/phase65-observation/yosaki.sqlite3`，若副本已存在则拒绝覆盖。副本保留阿夜已有经历和 owner 密码哈希；清除登录会话、API/MCP 密钥及可能带凭据的第三方端点，关闭全部 MCP 工具与服务和备份计划，暂停未结束会话。脚本不复制 `.secret_key` 或 `.chatgpt_plan`。
2. 在新 PowerShell 窗口运行 `.\scripts\start_phase65_observation.ps1`。脚本设置 `YOSAKI_DATA_DIR`、`YOSAKI_OBSERVATION_MODE=1` 和 `YOSAKI_CHATGPT_PLAN_ENABLED=1`，仅绑定 `127.0.0.1:8000` 并以前台单进程运行。不要让正式后端同时占同一端口。用原 owner 密码重新登录，在隔离实例的模型设置中手动授权套餐模型一次；不要复制正式实例的授权文件。
3. 每个香港日手动开始至多一轮自由活动：最长 10 分钟、活动判断最多 2 次、本地环境操作最多 2 次，体验回顾最多 1 次、心理评价最多 1 次，总调用最多 4 次。若先做 1 次 Phase 2 观察，活动判断减为 1 次。`allowed_tool_ids=[]`，只用本地探索室。反馈由 owner 逐项审阅。额度不足、超时或无效输出记作观察缺口，不切换付费 API，也不自动补跑。
4. 每天查看并导出 `/psychology` 的行为报告。第七个观察日结束后再讨论真实长期行为是否稳定。仅完成一次真实会话时，只能报告该次结果。

第 1 天使用隔离阿夜副本和重新授权的 `gpt-6.1-sol` 套餐档案。两次判断分别选择查看岬角地图页和旅行笔记，实际返回两个本地探索结果；会话因动作预算耗尽而正常结束，目标结果为 `partial`，不能解释成抵达旧灯塔。活动前乐趣预估 71/100，体验回顾 70/100，差值 -1。owner 审阅后应用短期好奇心调整：激活 0→约 0.01、抑制 0→约 0.02，满足度约 0.50 不变；形成一条长期学习来源证据，长期偏好没有自动批准。模型调用依次为活动判断两次、体验回顾一次、心理评价一次；预留输出 token 合计 2800，供应商返回的可信实际输出合计 772，单次耗时约 6.6～10.0 秒。当天没有 Phase 2 观察、MCP 调用或新活动。报告中的比例样本不足，不能据此判断长期行为趋势。

第 2 天继续参考上次的候选兴趣，先执行一次本地 `compare:map-notes` 操作，取得地图和旅行笔记都提到岬角东侧灯塔的**示例场景线索**，随后模型选择 `finish` 正常提前结束，没有把线索当作实地发现。目标仍为 `partial`；活动前乐趣预估与事后评分均为 64/100，差值 0。反馈首次应用遭遇驱力版本冲突，系统重新计算后经 owner 二次复核才应用：好奇心激活与满足度不变，短期抑制约 0.019409→0.037913。同一反馈只有一条驱力调节记录和一条心理反馈事件；长期学习证据累计两条，未自动批准偏好。两次活动判断、一次体验回顾和一次心理评价均成功，可信实际输出 token 合计 827/预留 2800，调用耗时约 9.0～11.7 秒。无 Phase 2 观察或 MCP 调用。行为报告显示跨会话关联同一候选兴趣，但仅两天样本，尚不能判断活动重复或兴趣趋同。

之后五个香港日只能分别由用户手动启动观察。若某日没有完成，应在该日记录缺口；不得补记成已观察、自动补跑或把两日闭环称为七日验收。

`tests/test_phase65.py` 在临时数据库中验证规则版本、同源去重、学习记忆去重、每日调用上限、隐私报告和 30 次脚本驱动的真实自由活动调度，包含三次本地环境操作、反馈审阅／应用及长期学习归集。`tests/test_phase6.py` 原有固定种子 100／500 次事件稳定性检查继续适用。30 次脚本选择证明链路和数值边界，不证明真实模型会自然变化。第三方 MCP、物理设备、多进程调度、公网部署和七日真实观察仍须分别验收。
